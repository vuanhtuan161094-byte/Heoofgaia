# P4.1 — Sprite Animation & Event-driven VFX Contract

Project: Mưu Định Tam Quốc · branch `main-ngoalong` · 16 November 2026.

## Deliverable

- **288 real exported PNG frames**: 4 unit classes (`infantry`, `cavalry`, `archer`, `strategist`) × 4 directions (`front`, `right`, `back`, `left`) × 3 actions (`idle`, `attack`, `hit`) × 6 frame images. Master retained in `assets/p4/troops.webp`. Frame sources are regenerated by `python tools/build_p41_atlas.py`; individual PNGs saved in `assets/p41/frames/` and CI source artifact rather than tracked 288 individual files.
- A single packed `assets/p41/troops_p41.webp` sprite atlas (8 columns × 36 rows; 800 × 5184 pixels). Foot/ground pivot at **(50, 137)** per 100 × 144 frame. Fixed 2D pixel compositing **NO skeletal rig, NO bones**.
- Deliberate honesty: the frames are **programmatically composited from two original P4 master poses**, with frame-specific light marks, motion staging and reaction sparks. This is bona fide frame-by-frame rendered PNG data, but **not** six independently hand-painted character poses. This release must not be called AAA-quality hand-drawn action animation or owner-approved art.
- On-screen animation loops Idle at ~8 fps, Attack at ~10 fps and Hit at ~10 fps, following authoritative battle events rather than changing battle state.
- Real battle event `actor/hits/mode/skill` drives 4 view-only phases: `charge` 0–210 ms, `release` 210–430 ms, `contact` 430–670 ms, `fade` 670–960 ms; non-skill hits still trigger contact. `dot` has no invented caster. Render speed follows battle speed.
- Replay uses actual saved snapshots; P4.1 VFX does **not** mutate HP, damage, morale, XP, loot or Save v3. It does not create additional receipts.
- P4 sources are independently AI-created imagery in this project's prior conversation. Nothing was extracted from Ngọa Long VNG. Existing P4 source provenance is retained.

## Quality and limitations

Quality controls: alpha islands (discard atlas-cell bleed), fixed transparent sprite registration, no external image dependency in runtime, four directions available in atlas (combat camera currently uses Right/Left), 1280 × 720 Chromium QA evidence and exact-SHA GitHub tests. No actual rigging, no pretense of 24 portrait completion. Some pose morph transitions are still synthetic and are a **visual approval gate**; image quality may need rework.

## Verification gates

1. Run `python tools/build_p41_atlas.py` and compare packed WebP SHA256 with source committed file (no mismatches permitted).
2. `python qa/p41_animation.py`: 18 independent checks of 288 frame files, combinations, alpha-independent image changes, event phases, gameplay-state read-only, Chromium screenshots.
3. `python qa/p41_video.py`: 52 genuine Chromium viewport frames at 1280 × 720 and 12 fps encoded as an MP4 with FFmpeg. Visual clock deliberately sampled; the combat events and hits were produced by the actual engine. This is **not an unmodified full-speed realtime gameplay capture**, nor physical device/FPS certification.
4. Keep P2 31+12, P3 74+360 scenarios, and P4 14+4 checks green at the same SHA.
5. CI artifact `ngoalong-p41-playable` only if all gates pass. QA report `qa/p41-video-report.json` includes the exact engine actors, hits, MP4 SHA, browser errors.
6. Physical Windows/Android validation, long-session performance, subjective owner visual acceptance remain PENDING.
